## Compose on WSLC

`wslc` cannot run a Compose file yet. From this version the agent runs
yours: it reads the file and does, one `wslc` command at a time, what the
file asks for. From a terminal with the new **`wslc-compose`** command, and
from the web interface and the Windows and Android clients.

### The `wslc-compose` command

- Installed with the agent and on your `PATH`: a command in any terminal
  opened after the install. On the agent's own machine it asks for no login
  and no token.
- Compose's own command line: `config`, `build`, `up`, `down`, `start`,
  `stop`, `restart`, `logs`, `ps`, `ls`, `version`, with the options you
  know (`-f`, `-p`, `--profile`, `--env-file`, `--no-cache`,
  `--remove-orphans`, `-v`, `--dry-run`) and services by name
  (`wslc-compose up -d web`). A script written for Compose has its first
  word changed and runs: every option Compose has is taken, and one that
  does nothing yet says so and goes on.
- `wslc-compose config` prints your file with a verdict on every line that
  needs one, before anything runs: converted (and into what), or not
  supported (and why).
- `up` saves the file as a project and brings it up in the order its
  services depend on each other, waiting for `service_healthy` and
  `service_completed_successfully`. Run again, it recreates only what
  changed, a rebuilt image included. Without `-d` it stays attached to the
  containers' logs; Ctrl+C stops them.
- A build drawn as Compose draws it, step by step, in colour. Services
  built from the same Dockerfile are built once.
- `logs`: one log for the project, each line said by its container (`-f`,
  `-n`, `-t`, `--since`).

Reference: [docs/compose/wslc-compose.md](https://github.com/Berpiztu/wslc-ai-agent/blob/main/docs/compose/wslc-compose.md).

### Projects in the web interface and the clients

- **Compose**, a new verb of the Containers page: open a Compose file or
  paste one, and **Check Compose file** shows it as a tree, every line with
  its verdict in colour. Then **Save** or **Run**.
- A project is one group on the Containers page, in rows and in cards: its
  name, its containers under it with a line round them, and its own start,
  stop, restart, logs, Compose file and remove.
- Start, stop and restart go through the project in order. A service whose
  dependency is stopped is not started, and stopping one that others need
  names them and asks first.
- A container that could not start turns red, says why on itself and in its
  log, and its project shows it too, on every client.
- Profiles and services by name, chosen in the Compose window and kept with
  the project.
- The same project everywhere: brought up from a terminal, it is on the
  Containers page, in the Windows app and on the phone.

### Also new

- The launch form, and a pasted `docker run` line, take labels, host and
  domain names, DNS servers, search domains and options, tmpfs mounts, shm
  size, ulimits and the stop signal.
- For AI agents: the MCP tool `parse_compose` reads a Compose file and says
  what would run on WSLC and what would be lost.
- A mount over a Windows junction or symbolic link, which WSLC does not
  follow, is converted so the container starts.

### Not there yet

Several Compose files read as one (`compose.override.yaml`, `include`,
`extends`), `secrets` and `configs`, `pull` and `exec`, bringing a project
up over MCP, and whatever `wslc run` has no flag for (`privileged`,
`cap_add`, `network_mode: host`). The whole list:
[Not there yet](https://github.com/Berpiztu/wslc-ai-agent/blob/main/docs/compose/wslc-compose.md#not-there-yet).

### Updating

```powershell
irm https://berpiztu.github.io/wslc-ai-agent/install.ps1 | iex
```

The agent's API goes from level 6 to 16, adding only: clients of an earlier
version keep working with this agent, and show the projects once updated.
