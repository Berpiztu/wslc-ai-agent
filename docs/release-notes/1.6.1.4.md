## Security: ASP.NET Core's remote code execution is fixed

This version is built on **.NET 10.0.13**, the security release of
13 October 2026. The agent serves its web page with ASP.NET Core, and every
.NET 10 before it, up to 10.0.12, carries two vulnerabilities of **high** severity
that allow **remote code execution**:
[CVE-2026-102870](https://github.com/advisories/GHSA-g27p-qf6j-c96c) and
[CVE-2026-96230](https://github.com/advisories/GHSA-qjpx-jqm5-h2c4).
Both are fixed here, in the agent and in the clients, which carry the
runtime inside, with the other fixes .NET 10.0.13 brings.

**Update every agent**, above all one reachable from another machine or
from the internet. Nothing else changes: settings, projects and dashboards
stay as they were.

## Previews only when you ask for them

Berpiztu publishes **previews**: pre-releases made for a WSL that is itself a
preview, such as WSL 3.0.4. An agent installed from an official release is
never offered one unless you say so: **Settings → Update → Include
pre-releases**, off until you switch it on, makes Latest on GitHub and
Install from GitHub offer the newest release of all, previews included. An
agent installed from a preview is always offered the next preview, or an
official release above it. Latest on GitHub says when what it offers is a
preview, and Install from GitHub installs that very release.

## Build on another machine: your sources travel as a tar archive

Until now a Compose file with a `build:` could only be built on the machine
that had the folder. From this version you build **on a remote agent from
the sources on your own machine**: the build context is packed as a tar archive, sent
to the agent, and built there with `wslc build`, which reads a context from
its standard input since **WSL 3.0.3**. The images are made where the
containers will run.

It is how a deployment on a server is updated from the desk that has the
new code: the sources go, and the server's own data folders stay where they
are and are mounted as they were.

### From the command line

```powershell
wslc-compose --agent https://server.example.com --token … up -d --build
✔ Build context .: 2 of 2516 files, 51.9 MB sent (9.1 KB); the agent had the rest
```

- **Packed as `docker build` packs it**: without what the folder's
  `.dockerignore` leaves out, the Dockerfile always in.
- **Only what the agent lacks is sent.** Every file is hashed first and the
  agent says which it does not have. The first time that is the whole
  folder; after it, a Dockerfile changed in a folder of fifty megabytes
  travels as a Dockerfile.
- **It says how far it has got** as it reads, packs and sends.
- **Nothing is unpacked on the agent's disk**: it keeps each file once,
  under its hash, and makes the archive for the build itself.
- `up --no-start` builds and creates the containers and leaves them
  stopped; `build` makes the images alone.

### From the Compose window

- The **Open Compose file** and **Context** buttons are a menu: **From this
  device** or **From the server**. A new picker shows the server's disk and
  its Compose files from any client.
- From this device, on another machine than the agent's, the window asks
  for the path of the folder the file is in, and then for the file. That
  folder is the context.
- **Save** and **Run** send what the images are built from, and do it
  **with the window closed**: the folder is read first, which takes
  seconds, the usual question is asked, and the sending goes on behind
  while the title bar's line and the transfers list say how far it has got.
- A project made this way is opened again (**View & edit**) as it was
  made: its file by the path it has on your machine, its context your
  folder. Saving it asks for the folder and sends what changed, or, in the
  same window, builds from **what the server has**: the folder as it was
  sent the last time, with nothing read from your device. That is how a
  variable is changed from a phone, or from any machine without the folder.
  The agent keeps those sources for as long as it keeps the project.

### One folder, the same on both machines

Only the sources travel. What the file mounts by a relative path, its
`.env` and its `env_file` are the server's, at the same path the project
has on your machine; a folder it mounts that is not there yet is made when
its containers start. A project that already lives somewhere on the server
stays there, and `--project-directory` names another place.

### The sending is one of the agent's transfers

It is in the transfers list of every client, with its progress and a cross
that stops it, and **the agent does not update itself while something is
travelling**.

## Also in this version

- **Warnings and errors are never lost.** Whatever a client shows as a
  warning or an error (a toast, the title bar's line, an error window, what
  `wslc-compose` prints) is written in the agent's log too. Warning toasts
  now stay until they are closed, as errors do.
- **Compose window**: a network or a volume the file names as `external`
  and the machine does not have is said on its line, and Save and Run stop
  in a window that names it, before anything is made. A branch of the
  file's tree takes the colour of the worst line in it, however deep.
- **Containers, as cards**: a project always begins a row, and so does the
  card after its last one, so two projects never share a row.
- **Containers**: each container's CPU and memory are read every five
  seconds again. With the agent's events on, they were read when something
  happened to a container and once a minute, so the reading taken as a
  container started, at its busiest, stayed on its dial for a minute.
- **File transfers**: a transfer that was cancelled, and one that went
  through, are said on the title bar's line and no longer in a toast; a
  cancel is no longer told as a failure of the network.
- **Host picker**: a line moves across the list while the server's folders
  are being read.
- **Nothing is left running behind an agent that was replaced.** Every
  `wslc` the agent starts now ends with it, however the agent goes. An
  agent closed by an installer left its `wslc events` listening to nobody,
  one more at every update. The ones earlier versions left go at the next
  sign-out, or can be ended from Task Manager.
- **A ring no longer turns after its work is over.** A project's card, or a
  container's, could go on showing *Working…* once a save, a start or a
  removal had ended, until the page was loaded again; with an agent far
  away it was the usual end of a save. The list is now drawn when a job
  ends, and a row's mark comes off the row it was put on. The same held for
  an image's pull, on the Images page.

## A Compose project has its card on the dashboard, with its CPU and memory

A project says what all its containers take, at a glance, in two places.

- **On the dashboard, a new ready-made card: Project card.** Drag it from
  the toolbox and choose a project: its name and how many of its containers
  run, their names, the **CPU** and the **memory** of all of them added up
  as two dials, the Compose file and the logs, and its verbs (start, stop,
  restart, down). Its pieces are objects as a container card's are, to move,
  resize or hide, and its dials take an alarm, which can show in the status
  bar of every screen.
- **One card, with its containers in it.** Choosing the project puts each
  of its containers inside the card, a container's card of its own there,
  with its line and its elevation, two to a row. The card's properties
  list its containers, each with a tick: ticked, it is shown in the card.
  A container made later is listed unticked, and the dashboard stays as you
  designed it until you tick it; one that was removed keeps its place, with
  nothing to read, as any object whose container is gone. A container
  wanted on its own is the Container card, as ever.
- **Designed as one, or one by one.** In design a container inside the card
  is taken and moved whole, as any card is, within the project's frame, and
  its pieces one by one after that. **Apply to every object** on the
  project's card reaches the cards inside it too: their line, their
  elevation and their colours with the project's. Out of design a tap on
  any of them takes the project's card.
- **Its line is the project's**, the one that runs round its cards in
  Containers: green with every container running, the primary colour with
  none, stripes of the two with some or while something is being done to
  it, and its header and its verbs pulse meanwhile.
- **In Containers, the project's card carries the same two dials.** Folded,
  a project said how many of its containers ran and nothing of what they
  took. The pointer on a dial lists each running container with its own
  share, so the one that takes the most is found without opening the group.
- **The round button says Add Compose**, on the Containers page and on the
  dashboard, where a project's card offers Run, Create and Add Compose as a
  container's does.

## Good to know

- The agent works with **WSL 3.0.0 or later**; the installer and
  `check-prereqs.ps1` say so of an older one.
- Building from a folder of another machine needs **WSL 3.0.3 or later on
  the agent's machine** (`wsl --update`). An older one is said before the
  build begins. Everything else works as before.
- In the Compose window, picking a folder of your device needs a
  Chromium browser (Chrome, Edge) over https, or the agent's own machine.
  A browser never tells a page where a folder is, so its path is asked for,
  in so many words, every time. The Android app cannot pick folders.
- A browser cannot open a file whose full path is longer than 260
  characters: such files are left out of what is sent, and named in a
  warning. `wslc-compose` reads them.
- The agent and `wslc-compose` have to be of this version on both sides to
  send a build context.
